Kindred — one job per sponsor, no overlap

Finds the people closest to you in meaning — then learns what “close” really means from which introductions actually land.

Stage 1 · understand
Gemini
Reads raw context into a semantic profile — trajectory and the explicit ask, not keywords. Also writes the per-edge reasoning shown on the graph.
POST /profile → {domain, prior_domain, stage, seeking, offering}
→
Stage 2 · retrieve
Actian
Vector store for every profile. Pulls the candidate neighbourhood — wide, by trajectory as well as topic — before anyone ranks it.
embed(profile) → top-k neighbours
→
Stage 3 · judge
Pioneer / Fastino
The fine-tuned match scorer. Trained on outcomes — landed vs didn’t — not on similarity. One yes/no question, thousands of times a generation, in milliseconds.
score_pair(a, b) → 0.0–1.0 · LoRA on gliner2-base-v1
→
Stage 4 · act
BAND
Opens the intro thread for a match that clears the bar, and is where the outcome becomes observable: did these two actually connect?
intro thread → landed = 1 / didn’t = 0
The loop BAND outcomes → Pioneer training set → refit → new weights → Actian re-ranks → the graph re-clusters on screen. Every sponsor sits on exactly one edge of that cycle, which is why the scorer can be swapped or frozen without touching anything else.
The rule we held to: one sponsor, one job, one artifact. Nothing is used twice and nothing is decorative — remove any box and the loop stops turning. Guild (optional): versions the weight vectors each generation emits.
